# تقرير التدقيق — الحالة قبل 3.0 (النسخة 2.0.0)

أُجري التدقيق بتشغيل الأدوات فعلاً لا بقراءتها فقط. كل بند أدناه إما «مُتحقَّق بتجربة» أو موسوم صراحةً بأنه استنتاج.

## 1. البنية الموجودة
```
SKILL.md                  ← سير عمل بثلاث بوابات (مقابلة ← سيناريو ← مشهد تجريبي ← إنتاج)
references/ (16 ملفاً)    ← تربية، جمهور، منصات، خطوط، بنك أمثلة، سكيمات (brief، master-script)
scripts/                  ← validate_script / validate_brief / voice_pack / mux_audio / retime_from_audio / check_output / doctor / aes_common
engine/                   ← قالب HTML/SVG واحد + render_scene (Playwright) + assemble + build + scriptlib + خطوط
```
مسار الإنتاج الوحيد المنفَّذ: «سبورة كرتونية 16:9» بثلاث شخصيات، تصيير حتمي الزمن، صوت من ملفات خارجية.

## 2. ما يعمل (مُتحقَّق بتجربة)
- بناء فيديو 44 ث من السيناريو إلى MP4 + SRT بأمر واحد، تزايدياً وبتصيير متوازٍ.
- فحص السيناريو (سكيما + تشكيل + توقيت + توافق المحرك).
- إعادة التوقيت من الصوت، وتنبيه الأسطر التي تغيّر نصها بعد التسجيل.
- فحص تقني للمخرج: مسارات، دقة، مدة، SRT، صمت، تشوّه، إطارات سوداء.

## 3. المخاوف المذكورة في الطلب — نتيجة التحقق
| المخاوف | النتيجة |
|---|---|
| `scene_template.html` و`render_scene.py` بلا تنفيذ | **غير صحيح الآن**: موجودان ويعملان (أُضيفا في 1.x وجُرّبا). |
| قوالب الدروس مواصفات لا أنظمة تنفيذية | **صحيح جزئياً**: النحو منفَّذ؛ الصرف والإملاء المتقابل والبلاغة والأصوات والعمودي مواصفات فقط (موسومة «مخطط» في `templates.md`). |
| معالجة أخطاء الصوت ناقصة | **صحيح**: `mux_audio` ينهار بـ `CalledProcessError` وتتبّع كامل إن كان الفيديو المصدر مفقوداً (جُرّب). |
| معالجة الحوار الفارغ | **جزئياً**: `voice_pack` و`mux` يتعاملان معه برسالة؛ لكن `validate_script` لا يحذّر من مشهد بلا حوار ولا أي حوار في الفيديو. |
| الأصول المفقودة / الصوت الأصلي | الأصول: `assemble` يرفع خطأً واضحاً. الصوت الأصلي: التصيير صامت دائماً و`mux` يستبدل المسار بالكامل (مقصود لكنه غير موثق). |
| التحقق بلا المكتبات الاختيارية | **صحيح، وأخطر مما ظُنّ**: بلا `jsonschema` ينهار `validate_script` بـ `TypeError` عند أي حقل بنوع خاطئ (جُرّب)، بدل أن يتحقق. |
| فحص الجودة تقني فقط | **صحيح**: لا فحص تعليمي أو بصري آلي (فيض النص، تداخل). |

## 4. مشاكل مكتشفة إضافية
1. **لا نظام حالة ولا موافقات ولا استئناف**: البوابات الثلاث وصفٌ في النص، لا كود.
2. **لا دعم لتلوين حرف داخل كلمة** (المحرك يلوّن كلمة كاملة فقط)، وهو شرط أي درس حروف.
3. **لا محقق لغوي حتمي**: صحة الأمثلة تعتمد على المؤلف.
4. **لا مفهوم للمزوّدين ولا للتكلفة**.
5. **منطق مكرر**: تعريف الحركات في ثلاثة ملفات (وُحّد في 2.0 داخل `aes_common` فبقي `scriptlib` يستورده).
6. المحرك يفترض 1920×1080 وثلاث شخصيات (موثق في `capabilities.json`).

## 5. مخاطر تقنية وأمنية
- **تنفيذ كود**: `build.py` و`mux` يستدعيان `ffmpeg` وPython بمسارات يمررها المستخدم. لا استخدام لـ`shell=True` (فحصت)؛ المخاطر: مسارات ملفات `concat.txt` بأسماء فيها `'` (تُعالَج بـ`as_posix` ولا تُهرَّب علامة الاقتباس — **ثغرة صغيرة قائمة**).
- **HTML مولَّد**: النص يُحقن في القالب عبر JSON داخل `<script>`؛ نص يحتوي `</script>` يكسر الصفحة. **قائم** (يُعالَج في 3.0).
- **تنزيل خطوط/CDN**: غير موجود؛ الخطوط محلية (جيد).
- **أسرار**: لا مفاتيح في الحزمة. المزوّدون الخارجيون في 3.0 يقرؤون المفاتيح من متغيرات البيئة فقط ولا تُكتب في ملفات المشروع.
- **اعتمادية**: Python ≥ 3.9، ffmpeg/ffprobe، Playwright + Chromium، jsonschema (اختيارية بعد 3.0).
